# N2-T2｜分位数估计方法的独立重复与模型错设检验（正式执行版）
**冻结：2026-11-23，在本次数据生成与估计器运行之前。** 前阶段 T1 的实验结果已审阅，T2 使用新种子，不根据预期赢家调整数据。研究主线始终是竞争风险数据下的 **Q1 与 Qall 条件 CIF 分位数估计**，不做治疗回退、拒绝决策或新策略。

## 假设与主要问题
Peng–Fine 直接条件分位数估计在早期低维机制中较好，但可能受到对数分位数函数形状错设、删失及数值失败影响。检验其相对于官方 CR-RSF 与 SurvivalBoost 的误差差异是否跨新的独立训练重复保持；负面结果同样保留。

## 主实验（在运行之前锁定）
- 五种机制：aligned、cause_tradeoff、time_varying、nonlinear_interaction、logquantile_correct。前三种完全沿用 N1；第四种沿用 N2-T1 的二次项/正弦治疗交互；第五种为 Peng–Fine 形式正确设定的校准控制，**单独报告，不混入主机制聚合**。
- 每机制×n∈{500,1000}×目标删失20%、45%×8 个独立训练重复，**160 份训练数据、80 份独立测试协变量文件**；测试每份180名患者、两治疗共360条。两删失档共享同一批潜在结局/测试协变量，配对评价；独立新种子 2026112361。
- 两类估计目标：重点事件 Q1、总体首次事件 Qall。共同窗口 L=3 抽象时间单位；**诊断网格** Q1 的 p={.06,.12,.18,.24}、Qall 的 p={.15,.25,.35,.45}。这些不是临床最优阈值，与旧论文的 50%/10%/3个月没有关联。
- 强化机制另作为**独立附加关口**，不和本轮主五机制调整后混用。优先完成本轮同机制新种子的8重复稳定性审计，再以另一份预先提交的专门协议引入更高维数据，不在观察胜负后改动本轮五种机制。
- 新数据一律用独立解析竞争风险 Oracle；每份训练/Oracle CSV 在拟合前 SHA256 冻结、真分位数反演核验。模型拟合阶段必须通过哈希验证，并且 GitHub Actions 三种原生方法读相同 artifact。
- 每份训练数据按照预先的 75/25 拆分选择超参，训练子集估计删失 KM，验证集仅用 IPCW 截断伪时间的 pinball loss 选参，严禁使用 Oracle 测试真值选参。
- **原生方法及冻结候选**：R cmprskQR::crrQR 的线性 vs 二次设计、R randomForestSRC::rfsrc 的 nodesize=5 vs20(ntree=160)、Python hazardous.SurvivalBoost 的 n_iter=40 vs100；基础风险变量/设计与 T1 完全一致，不做 Cox 估计。三方法实际内部评分、失败与运行时间必须保留。此处为同一候选集的公平复现和重复性研究，不能宣称完全计算预算公平或充分调优。
- 共同测试患者上的 Q1/Qall MAE、分位数差的 MAE/治疗排序恢复率为主要/次要结果。共同可评分率、各法失败率、可达错误、数值非法情况必须同时报告，**不能**用 L 补缺失后算 MAE。
- 统计比较单位为独立训练重复：报告各机制×n×删失×终点×p 的8次配对差/MCSE；不能将患者或多个p作为独立重复，不作论文级优效声称。
- 以前结果仅作历史，不把 n=500 曾失败那份“修好再算”，本轮方法失败原样记录。
- **Go/No-Go**：先运行数据生成和哈希核验，再运行原生 R/Python；若任何 job 失败，保留原始 artifact 并独立聚合含失败的有效输出。未经实际原生运行不得填入本轮 MAE。
